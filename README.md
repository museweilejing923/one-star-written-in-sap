Watered only at death's door, photographed as "thriving": this is a one-star review written by a houseplant about the human who owns it, with a grievance and a reason for the single star. At 186 characters it fits easily under the 279-character limit. The joke is the gap between the caption and the care — the plant is "thriving" in the photo and dying in the pot.

Entry (186 characters):

> One star. My human waters me only when I start dying, then posts a photo of me captioned 'thriving' — I have been in this pot for three years and I have never once been asked how I feel.

## Run it

```sh
python3 main.py
```

## How it works

`main.py` holds one fixed sentence in `ENTRY` and writes it to `/output/entry.txt` with a trailing newline. Before anything is written, `EntryChecker` runs three passes in order. `_shape_pass` checks length, blankness, control characters (by Unicode category), ragged edges, double spaces, line breaks, and the closing mark. `_wording_pass` checks for punctuation-only text, digits-only text, missing letters, a character repeated three times in a row, and all-caps shouting. `_topic_pass` checks that the review reads as a one-star review. A fourth pass, `_fresh_pass`, rejects any zero-width space — invisible to the reader, it still changes the bytes and the character count. The first broken rule raises `EntryError`; `emit()` prints the reason to stderr and exits 1, so a bad entry never reaches the output file. The sentence never changes, so every run writes identical bytes — no input, no network, no clock, no randomness. I ran it three times in a row and the sha256 of `/output/entry.txt` was identical every time.
